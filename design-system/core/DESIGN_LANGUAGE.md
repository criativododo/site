# DESIGN_LANGUAGE

> Fonte soberana da linguagem de design do Criativo DODÔ.
>
> Este documento define princípios permanentes.
> Não define componentes, tokens, cores, tipografia ou tecnologia.
> Toda decisão de design deve ser compatível com estes princípios.

---

# 1. Propósito

O DODÔ existe para reduzir complexidade sem reduzir personalidade.

Nossa interface não busca impressionar.
Busca tornar ideias, estratégias e decisões imediatamente compreensíveis.

O design nunca é o protagonista.

O conteúdo é.

---

# 2. Os princípios permanentes

## Clareza antes da estética

Toda decisão deve tornar o conteúdo mais compreensível.

Nunca mais bonito às custas da compreensão.

---

## O conteúdo é soberano

A interface existe para servir.

Chrome, cor, movimento, tipografia e estrutura nunca competem com o conteúdo.

---

## Um contexto por vez

Cada tela, documento ou fluxo deve responder uma única pergunta.

Misturar contextos aumenta carga cognitiva.

---

## Menos decisões, mais direção

O sistema deve reduzir escolhas desnecessárias.

Boas interfaces orientam.

Não perguntam o tempo inteiro.

---

## Movimento explica

Motion existe apenas para:

- explicar;
- orientar;
- confirmar.

Nunca para decorar.

---

## Cor comunica intenção

Cor possui significado.

Nunca ornamentação.

Toda cor deve responder:

"O que isto comunica?"

---

## Tipografia conduz a leitura

Tipografia organiza pensamento.

Não demonstra estilo.

Hierarquia nasce por contraste, ritmo e espaço.

---

## O sistema desaparece

A melhor interface é aquela que deixa o usuário esquecer que existe uma interface.

---

## Artesanato importa

Cada detalhe comunica cuidado.

Precisão transmite confiança.

---

## Evoluir sem quebrar

A linguagem pode crescer.

Nunca perder sua identidade.

Novas decisões devem fortalecer os princípios existentes.

Nunca criar exceções.

---

# 3. O que NÃO pertence aqui

Este documento nunca deve conter:

- componentes;
- CSS;
- tokens;
- valores;
- pixels;
- hexadecimais;
- fontes;
- implementações;
- regras específicas de frameworks.

Essas decisões pertencem ao Design System.

# 5. Teste final

Toda decisão de design deve responder:

• torna o conteúdo mais claro?

• reduz carga cognitiva?

• respeita um único contexto?

• elimina ruído?

• possui intenção?

Se qualquer resposta for "não",

a decisão deve ser redesenhada.
