# CHANGELOG

> Registro cronológico da evolução da Design Language do Criativo DODÔ.
>
> Este documento registra apenas mudanças que alteram a forma como pensamos, projetamos ou documentamos a linguagem do produto.
>
> O histórico de código pertence ao Git.
> O motivo das decisões pertence ao `DECISIONS.md`.
> Este arquivo registra apenas o que mudou na documentação oficial.

---

# Como registrar mudanças

Registrar apenas alterações que mudam o comportamento da Design Language.

Exemplos:

- criação de novos documentos;
- novos princípios;
- revisão de regras permanentes;
- remoção de referências;
- reorganização da arquitetura documental.

Nunca registrar:

- commits;
- correções ortográficas;
- reorganização de texto;
- ajustes de formatação;
- mudanças de CSS;
- implementação de componentes.

# Regras permanentes

Escrever sempre para humanos.

Registrar apenas mudanças perceptíveis.

Agrupar alterações relacionadas.

Uma mudança deve aparecer apenas uma vez.

Nunca copiar mensagens de commit.

Nunca explicar implementação técnica.

O CHANGELOG comunica evolução.

Não desenvolvimento.
